# Altenar.com — инструкции для агента

Маркетинговый сайт Altenar из двух страниц: **Home** (`/`) и **Turnkey Sportsbook** (`/Sportsbook/`). Vite 8 + React 19 + GSAP, MPA. Проект изначально собран в ChatGPT/Codex, дорабатывается в Claude. Пользователь — Борис, senior product designer / art director: общаемся по-русски, коротко и по делу, решения по дизайну за ним.

## Главные правила

- Делай только то, что попросили. Утверждённые английские тексты, геометрию, цвета, ассеты, ссылки, анимации и интерактив не трогай без прямого запроса. Новые или заменённые иллюстрации — только по запросу.
- Правку одной страницы делай локально (её данные, разметка, адаптер). Общий компонент меняй, только если правка нужна обеим страницам, и проверяй обе. Различия общих компонентов оформляй явными вариантами (`data-*`-атрибут или опция), а не переопределениями со стороны страницы.
- Коммит, push, публикация и деплой — только по прямой просьбе.
- Не выдавай непроверенное за проверенное: «собрал», «проверил в браузере», «работает» пишется только после фактического результата инструмента. Что не проверил — так и скажи.

## Где что лежит

Рабочая папка — `altenar-combined-claude`. Рядом лежит `altenar-combined` без суффикса — это версия ChatGPT, её не редактируем. `altenar-home-page/`, `altenar-turnkey/` и ZIP-архивы — справочные версии, и обычно их нет в подключённых папках: если нужны для сравнения, попроси доступ.

| Что | Где |
| --- | --- |
| Home: точка входа | `index.html` → `src/premium/main.ts` → импортирует `src/main.tsx` |
| Home: секции и анимации | `src/premium/` (секции, glow-тема в `src/premium/glow/`), базовые модули в корне `src/` (`sections.ts`, `morph.ts`, `rollover.ts`, `video.ts`, `*-motion.ts`) |
| Turnkey: точка входа | `Sportsbook/index.html` → `src/shared/sportsbook.ts` (общие модули) + готовые бандлы `public/_turnkey/assets/*.js`. Исходников Turnkey нет |
| Общие компоненты | `src/shared/` — типографика, меню, кнопки, стрелки, FAQ, Contact, Footer. Подробности в [docs/DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md) |
| Глобус | `public/shared/globe.js` и `globe.css` (рендерер Mappo) |
| Данные | `src/*.json`, `src/premium/*.json`, корневые `*-map.json`, `country-popup-data.json` |
| Медиа | `public/` (~300 МБ: видео, фото, шрифты) |
| Сборка | `dist/` — генерируется, руками не править |

Страница Turnkey — `Sportsbook/index.html`. Перед правкой Turnkey проверь, какие файлы из `public/_turnkey/` она реально подключает: часть бандлов там может быть неиспользуемой.

Правка Turnkey: сначала общий модуль или адаптер в `src/shared/sportsbook.ts`. Если без правки бандла не обойтись — меняй только подключённый файл и только нужный участок, и скажи об этом в отчёте.

Эта папка — личная копия проекта для Claude: лишнее можно удалять, но только то, что точно не подключено (проверь через `rg`). Старая версия этой инструкции для ChatGPT есть в git-истории (коммит `dc62698`).

## Источники дизайна

| Элемент | Эталон |

## Запуск и окружение Claude

Node 22.12+ (`.nvmrc`: 22). Команды из корня проекта:

| Действие | Команда |
| --- | --- |
| Установить зависимости (первый запуск, смена lockfile) | `npm ci` |
| Dev-сервер | `npm run dev` → `http://127.0.0.1:4173/` |
| Сборка | `npm run build` |
| Просмотр сборки | `npm run preview` |

Как это устроено в сессии Claude:

- Файлы проекта лежат на Mac Бориса. Читаю и правлю их через shell устройства (`device_bash`, папка смонтирована в `$HOME/mnt/altenar-combined-claude`). Это Linux-VM, а не сам macOS: процесс, запущенный там, из браузера на Mac не виден.
- Смотреть страницу Борис и я можем, только когда сервер запущен на самом Mac. Для этого в корне есть `dev.command`: двойной клик в Finder запускает `npm run dev` в Терминале и открывает сайт. Если сервер уже работает (Терминал открыт), новый не запускай: Vite сам подхватывает правки в `src/`.
- Браузерная проверка — во встроенном браузере Claude по `http://127.0.0.1:4173/` и `/Sportsbook/`. По умолчанию ширина около 800px: это не десктоп, учитывай при оценке раскладки.
- Удаление файлов в папке по умолчанию запрещено в каждой новой сессии, и без него падают `vite` (чистка кэша `node_modules/.vite`), `vite build` (чистка `dist/`) и git (lock-файлы). Борис разрешает удаление в этой папке, так что в начале сессии сразу запроси его (`device_request_delete_permission`). Путь папки бери из `get_device_info.connectedFolders`.
- Git: user.name и user.email в репозитории не заданы, коммить через `git -c user.name=Boris -c user.email=…`. Коммиты делаю по просьбе, push — только по прямой просьбе (remote не настроен).

## Как работать

1. Определи, что именно меняется и что может сломаться. Для локальной правки смотри только нужную область: `rg` по селектору, классу или тексту, а не чтение всего проекта.
2. Сделай минимальную законченную правку. Существующие состояния и вызовы не ломай.
3. Проверь по риску (таблица ниже) и коротко отчитайся: что сделано, что проверено, что нет и почему.

| Риск | Что проверить |
| --- | --- |
| Низкий: текст, локальный стиль | Дифф и сам блок в браузере |
| Средний: компонент, интерактивный блок | Сборка, начальное состояние, hover и click, повторное взаимодействие, обратная прокрутка |
| Высокий: общие стили, навигация, скролл-анимации, перенос между страницами | Обе страницы, границы секций, состояния прокрутки, переходы, консоль |

По умолчанию проверяй десктоп. Мобильную и планшетную ширину добавляй, когда правка затрагивает переносы, размеры или раскладку.

Инварианты, которые легко сломать:

- Меню над hero и после прокрутки, раскрытие Solutions, ссылки.
- Кнопки: геометрия, цвета, стрелка ходит по X без вращения.
- Глобус: автовращение, drag, инерция; вертикальная прокрутка страницы при этом работает.
- Форма Contact: все шаги, hover, валидация, ничего не обрезано, CTA стоит на месте и не прыгает по высоте.
- Карусели и карточки: смена, обратный переход. FAQ: раскрытие и повторное раскрытие.
- Footer: структура, раскрытие при прокрутке, медиа.
- Анимации: без вспышек и скачков, срабатывают повторно и при обратной прокрутке.

Делегирование субагентам — только когда Борис просит или когда задача реально распадается на независимые части (например, аудит двух страниц параллельно). Интеграцию и итоговую проверку делаю сам.

## Модель, усилие и экономия контекста

Модель и уровень усилий (effort) переключает Борис: `/model` и настройки сессии. Я сам их не меняю, но в начале задачи коротко говорю, если текущий выбор явно избыточен или слабоват.

| Задача | Модель | Effort |
| --- | --- | --- |
| Замена текста, поиск файла, правка ссылки, сверка списков | Haiku | low |
| Локальный CSS, отступы, один блок, сравнение со скриншотом | Sonnet | low–medium |
| Компонент с состояниями, React-логика, адаптив секции | Sonnet или Opus | medium |
| Общие компоненты, GSAP и скролл-анимации, перенос между страницами | Opus | high |
| Регрессия, которую не удалось найти с двух заходов, архитектурный конфликт | Fable / Opus | xhigh–max |

Объём работы сам по себе не повод брать модель старше: много однотипных правок — это Sonnet, а не Opus. Поднимать уровень стоит после реального сбоя, а не заранее.

Как не тратить контекст:

- Минифицированные бандлы в `public/_turnkey/assets/*.js` целиком не читаю: только `rg -o` по нужному селектору или фрагменту с небольшим окном вокруг. То же для `dist/`, `node_modules/` и больших JSON.
- Файлы читаю диапазонами (`sed -n`, `head`), вывод команд обрезаю до нужного (`| head`, `--stat`, `--short`).
- Браузер: скриншоты в масштабе 0.4–0.5 или зум на конкретный блок; консоль только с `onlyErrors`; `find` по элементу вместо полного дерева `read_page`.
- Широкий поиск по проекту отдаю субагенту Explore: в основной контекст возвращается вывод, а не дампы файлов. Механическую подзадачу субагенту можно поручить с `model: haiku`.
- Повторно не перечитываю то, что уже есть в контексте. Решения, которые нужны и в следующих сессиях, записываю сюда, а не пересказываю каждый раз.
- Длинную сессию после законченного блока работы лучше закрыть и начать новую (или `/compact`): контекст из этого файла подхватится заново.

## Контент и цифры

- Английский текст на сайте утверждён. Меняй его только по запросу. Предложения из Notion, скриншотов и документов — материал для работы, а не разрешение на правку.
- Для новой цифры или продуктового утверждения нужны источник, период, охват и единицы. Публичность показателя подтверждает владелец данных. Демонстрационные и исторические данные помечай.
- Не путай turnover и GGR. Терминальные ставки анонимны, связи online ↔ retail указывай только подтверждённые. Если данных не хватает, оставь текущее значение и скажи, чего недостаёт.

## Публикация

Живая версия сайта выложена через ChatGPT Sites из другой папки, из этой копии туда не публикую. При любой выкладке статика берётся из `dist/`, а маршрут `/Sportsbook/` должен отдавать `Sportsbook/index.html`. Если Борис попросит выложить сайт, сначала обсудим, куда и как. Помни: `public/` весит около 300 МБ, прошлую выкладку пришлось делить на части из-за лимита в 64 МБ на одну передачу.
