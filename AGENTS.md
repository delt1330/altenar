# Altenar.com — инструкции для агента

Маркетинговый сайт Altenar из двух страниц: **Home** (`/`) и **Turnkey Sportsbook** (`/Sportsbook/`). Vite 8, React 19, GSAP, многостраничная сборка. Проект начат в ChatGPT/Codex, дорабатывается в Claude. Пользователь — Борис, senior product designer / art director. Общаемся по-русски, коротко и по делу; решения по дизайну принимает он.

## Главные правила

- Делай только то, что попросили. Утверждённые английские тексты, геометрию, цвета, ассеты, ссылки, анимации и интерактив без прямого запроса не трогай. Новые или заменённые иллюстрации — только по запросу.
- Правку одной страницы делай в её коде (данные, разметка, адаптер). Общий компонент меняй, только если правка нужна обеим страницам, и тогда проверяй обе. Различия общих компонентов оформляй явным вариантом (`data-*`-атрибут или опция), а не переопределением со стороны страницы.
- Законченную правку сам коммичу и пушу в `main` — это и есть публикация, Борису ничего запускать не нужно. Промежуточные шаги, которые он ещё не видел и не одобрил, отдельно не коммичу.
- После каждого push первой строкой ответа — ссылка на страницу с изменением, без пересказа шагов (подробнее в «Публикации»).
- Не выдавай непроверенное за проверенное: «собрал», «проверил в браузере», «работает» пишу только после фактического результата инструмента. Что не проверил, так и говорю.

Рабочая папка — `altenar-combined-claude`, это личная копия проекта для Claude. Лишнее из неё можно удалять, но только то, что точно нигде не подключено (проверь через `rg`). Соседняя `altenar-combined` — версия ChatGPT, её не редактируем. `altenar-home-page/`, `altenar-turnkey/` и ZIP-архивы — справочные версии; если нужны для сравнения, попроси доступ. Старая инструкция для ChatGPT — в коммите `dc62698`.

## Окружение и команды

Node 22.12+ (`.nvmrc`: 22). Команды из корня проекта:

| Действие | Команда |
| --- | --- |
| Зависимости (первый запуск, смена lockfile) | `npm ci` |
| Dev-сервер | `npm run dev` → `http://127.0.0.1:4173/` |
| Сборка | `npm run build` |
| Просмотр сборки | `npm run preview` |

**Claude Code на Mac (основной режим).** Shell, git и браузер работают прямо на Mac Бориса.

- Dev-сервер обычно уже запущен через `dev.command` (двойной клик в Finder открывает Терминал с `npm run dev`). Проверка: `lsof -iTCP:4173 -sTCP:LISTEN`. Если порт слушается, второй сервер не запускай, просто открой `http://127.0.0.1:4173/` во встроенном браузере: Vite сам подхватывает правки. Если не слушается — `preview_start` с конфигом `dev` из `.claude/launch.json`.
- Встроенный браузер по умолчанию узкий (около 800px), это не десктоп. Для проверки десктопа выставляй `resize_window` 1440×900, в конце сбрасывай пресетом `desktop`.
- Git: `user.name` и `user.email` в репозитории не заданы, коммить через `git -c user.name=Boris -c user.email=<адрес Бориса из контекста сессии>`. Push — обычный `git push origin main` (доступ через `gh` и Keychain). В папке могут параллельно работать другие сессии: перед коммитом проверь `git status` и добавляй только свои файлы, перед push сделай `git pull --rebase --autostash`.

**claude.ai с доступом к Mac через `device_bash` (запасной режим).** Папка смонтирована в Linux-VM (`$HOME/mnt/altenar-combined-claude`, путь — из `get_device_info.connectedFolders`), процессы оттуда браузеру на Mac не видны.

- В начале сессии запроси удаление файлов (`device_request_delete_permission`), Борис его разрешает. Без этого падают `vite` (кэш `node_modules/.vite`), `vite build` (чистка `dist/`) и git (lock-файлы).
- Push через облачный контейнер: `add_repo` (delt1330/altenar, push) и `git clone --depth 1` в `/home/claude/altenar`. На Mac — `git bundle create .git/claude-relay/out.bundle origin/main..main` и `device_stage_files`. В контейнере — `git fetch origin main`, `git fetch <bundle> main:relay`, `git push origin relay:main`. Затем на Mac — `git update-ref refs/remotes/origin/main <новый sha>` и удалить `.git/claude-relay/`.
- Если и это не вышло, запасной путь — `push-to-github.command` в корне (исключён из git): Борис запускает его двойным кликом.

## Публикация

Хостинг — GitHub Pages из публичного `github.com/delt1330/altenar`, ветка `main`. До слияния в этом репозитории жил другой проект, его история сохранена. Старый приватный `altenar-site` больше не используется. Workflow `.github/workflows/deploy.yml` собирает сайт после каждого push, обычно за 1–3 минуты.

Ссылка после push: **https://delt1330.github.io/altenar/** и/или **https://delt1330.github.io/altenar/Sportsbook/** — смотря что менялось. Перед отправкой дождись конца деплоя (`gh run list --workflow deploy.yml -L 1`) и убедись, что изменение видно на странице (встроенный браузер или WebFetch). Пока идёт деплой, для быстрой проверки есть локальный `http://127.0.0.1:4173/`.

Сайт живёт в подпапке `/altenar/`, а исходники пишутся от корня (`/glow-media/…`, `/Sportsbook/`). При сборке для Pages:

- `BASE_PATH=/altenar/` задаёт Vite `base`;
- `scripts/rebase-dist.mjs` дописывает `/altenar` ко всем путям от корня в `dist/` (код, CSS, JSON, бандлы Turnkey).

Новые пути пиши от корня (`/glow-media/x.png`): скрипт их подхватит, если папка лежит в `public/`. Ссылку на главную — только через `import.meta.env.BASE_URL`, не `'/'`. Проверка сборки под подпапкой: `BASE_PATH=/altenar/ npm run build && BASE_PATH=/altenar/ node scripts/rebase-dist.mjs`, затем открыть `dist` под `/altenar/` и убедиться, что нет 404.

Лимит Pages — 1 ГБ на сайт. Версия для ChatGPT Sites выкладывается из другой папки, отсюда туда не публикую.

## Как работать

1. Определи, что меняется и что может сломаться. Для локальной правки смотри только нужную область: `rg` по селектору, классу или тексту, а не чтение всего проекта.
2. Сделай минимальную законченную правку, не ломая существующие состояния и вызовы.
3. Проверь по риску и коротко отчитайся: что сделано, что проверено, что нет и почему.

| Риск | Что проверить |
| --- | --- |
| Низкий: текст, локальный стиль | Дифф и сам блок в браузере |
| Средний: компонент, интерактивный блок | Сборка, начальное состояние, hover и click, повторное взаимодействие, обратная прокрутка |
| Высокий: общие стили, навигация, скролл-анимации, перенос между страницами | Обе страницы, границы секций, состояния прокрутки, переходы, консоль |

По умолчанию проверяй десктоп. Мобильную и планшетную ширину добавляй, когда правка затрагивает переносы, размеры или раскладку.

Что легко сломать:

- Меню над hero и после прокрутки, раскрытие Solutions, ссылки.
- Кнопки: геометрия, цвета, стрелка ходит по X без вращения.
- Глобус: автовращение, drag, инерция; вертикальная прокрутка страницы при этом работает.
- Форма Contact: все шаги, hover, валидация, ничего не обрезано, CTA стоит на месте и не прыгает по высоте.
- Карусели и карточки: смена и обратный переход. FAQ: раскрытие и повторное раскрытие.
- Footer: структура, раскрытие при прокрутке, медиа.
- Анимации: без вспышек и скачков, срабатывают повторно и при обратной прокрутке.

Субагентам задачу отдаю, только когда Борис просит или когда она реально распадается на независимые части (например, аудит двух страниц параллельно). Интеграцию и итоговую проверку делаю сам.

## Контент и цифры

- Английский текст на сайте утверждён, меняй его только по запросу. Предложения из Notion, скриншотов и документов — материал для работы, а не разрешение на правку.
- Для новой цифры или продуктового утверждения нужны источник, период, охват и единицы. Публичность показателя подтверждает владелец данных. Демонстрационные и исторические данные помечай.
- Не путай turnover и GGR. Терминальные ставки анонимны, связи online ↔ retail указывай только подтверждённые. Если данных не хватает, оставь текущее значение и скажи, чего недостаёт.

## Модель и контекст

Модель и effort переключает Борис в настройках сессии, сам я их не меняю. В начале задачи коротко говорю, если текущий выбор явно избыточен или слабоват.

| Задача | Модель | Effort |
| --- | --- | --- |
| Замена текста, поиск файла, правка ссылки, сверка списков | Haiku | low |
| Локальный CSS, отступы, один блок, сравнение со скриншотом | Sonnet | low–medium |
| Компонент с состояниями, React-логика, адаптив секции | Sonnet или Opus | medium |
| Общие компоненты, GSAP и скролл-анимации, перенос между страницами | Opus | high |
| Регрессия, не найденная с двух заходов; архитектурный конфликт | Fable или Opus | xhigh–max |

Объём сам по себе не повод брать модель старше: много однотипных правок — это Sonnet. Уровень поднимаю после реального сбоя, а не заранее.

Экономия контекста:

- Минифицированные бандлы `public/_turnkey/`, `dist/`, `node_modules/` и большие JSON целиком не читаю: только `rg -o` по нужному фрагменту с небольшим окном вокруг.
- Файлы читаю диапазонами, вывод команд обрезаю (`| head`, `--stat`, `--short`).
- Браузер: скриншоты в масштабе 0.4–0.5 или зум на блок, консоль с `onlyErrors`, `find` по элементу вместо полного `read_page`.
- Широкий поиск по проекту отдаю субагенту Explore, механическую подзадачу — субагенту с `model: haiku`.
- То, что уже есть в контексте, не перечитываю. Решения, нужные и в следующих сессиях, записываю сюда.
- После законченного блока работы длинную сессию лучше закрыть и начать новую (или `/compact`): этот файл подхватится заново.
